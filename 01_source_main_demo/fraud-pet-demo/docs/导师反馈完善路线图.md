# 导师反馈完善路线图

> 基于导师 5 点要求：UI 简洁明了清晰 / 不局限于本地、能联网 / 低门槛、下载/打开网页直接用 / 交付落地、日常使用 / 不做演示模拟。
>
> 诊断结论：系统**技术底座已支持真实产品**（账号密码体系、LLM 接入、Docker、Postgres/CAS/S3 配置项均存在），但目前运行态和前端仍停留在“演示态”。完善的关键是**关闭演示态、简化 UI、完成联网部署**。

---

## 一、导师要求 ↔ 当前差距

| 导师要求 | 当前现状 | 核心差距 |
|---|---|---|
| UI 简洁、明了、清晰 | 登录页含渐变光晕/浮动粒子/玻璃态/ Feature 网格；首页 Bento 卡片密集、渐变条多 | 装饰元素过载，信息层级被稀释 |
| 不局限于本地、能联网 | `docker-compose.yml` 仅映射本地端口；登录页仍写“离线可运行 · 数据本地化” | 未部署到公网，且文案仍在强调“本地/离线” |
| 低门槛：下载客户端或打开网页，输入账号密码即用 | 登录页有“演示账号一键进入”“校方发布端入口”等 Demo 按钮；多处代码硬编码 `ownerId='U-2408**'` 回退 | 真实注册/登录入口被 Demo 入口冲淡，且无密码重置 |
| 交付落地、日常使用 | `.env` 中 `AUTH_REQUIRED=false`、`CAMPUS_AUTH_MODE=demo`；内容以种子数据为主 | 默认走模拟逻辑，缺乏每日提醒、内容更新机制 |
| 不做演示/模拟 | 大量“演示态”“示例大学”“离线运行”标签；能力画像/知识库近期才修正为多主题 | 需彻底去除“这是 Demo”的心理暗示，按真实 SaaS 标准打磨 |

## 二、四阶段完善路线

### Phase 1：关闭演示态（1–2 天，最高优先级）

目标：让系统看起来像真实可用的产品，而不是 Demo。

1. **登录入口真实化**
   - 删除 `LoginPage.tsx` 中的「演示账号一键进入」按钮。
   - 删除「校方发布端入口」的显眼按钮（仅保留 `/login` 表单内的角色切换或独立后台登录页）。
   - 默认进入 `/login`，不再自动 Demo 登录。
   - 文案从“大学生反诈主题学习…”改为修正后的定位“大学生 AI 主题学习与成果展示平台”。
2. **后端强制鉴权**
   - 将 `.env` 中 `AUTH_REQUIRED=false` 改为 `true`。
   - 移除 `ownerId` 查询参数回退，敏感接口必须带合法 `Bearer Token`。
   - 删除/收敛所有 `ownerId || 'U-2408**'` 硬编码回退（`useAppStore.ts`、各 API 调用处）。
3. **去掉“离线/本地化”暗示**
   - 删除登录页“离线可运行 · 数据本地化”标签。
   - 删除“匿名主人 ID · 不采集真实身份”等 Demo 说明，改为真实隐私政策说明。
4. **账号体系闭环**
   - 增加“忘记密码”流程（邮箱/手机验证码，或先落地为校内管理员重置）。
   - 注册后引导完成首次测评，而不是直接进首页。

### Phase 2：UI 商业化简洁改造（3–5 天）

目标：符合“商业软件的 UI 简洁、明了、清晰”。

1. **登录页重构**
   - 移除径向光晕、网格背景、浮动粒子、玻璃态卡片。
   - 改为白底/浅灰底 + 品牌色强调，左右两栏（品牌文案 + 登录卡片）或居中卡片。
   - 减少左侧 Feature 网格（3 个图标）为一句话价值主张即可。
2. **首页信息层级精简**
   - 减少 Bento 卡片数量，把“今日训练 / AI 任务包 / 可疑信息检测 / 我可能被骗了”合并为 2–3 个核心入口。
   - 去除进度条渐变，使用单一品牌色。
   - 弱化宠物卡片视觉权重，突出“能力画像”和“今日任务”。
3. **建立设计系统**
   - 统一色彩：品牌色 1 个 + 中性色 + 语义色（成功/警告/危险）。
   - 统一卡片：白底、细边框、圆角一致，不用玻璃态/阴影堆叠。
   - 统一字体层级：标题/正文/辅助文本只保留 3–4 级。
4. **移动端优先**
   - 登录页、首页、测评页、情景训练页在 375px 下走查一遍。

### Phase 3：联网部署与真实 AI（2–3 天）

目标：任何人打开网址即可使用。

1. **公网部署**
   - 选择任一方案：
     - CloudStudio / 自有云服务器 + Nginx 反代；
     - Railway / Render / 阿里云 ECS / 腾讯云轻量。
   - 配置域名 + HTTPS（Let’s Encrypt 或云平台证书）。
   - `vite.config.ts` 中将 `/api` 代理改为生产域名。
2. **数据库切换**
   - 从 SQLite 切到 PostgreSQL（`DATABASE_URL`）。
   - 保留 SQLite 用于本地开发，生产环境用 Postgres 镜像。
3. **真实 LLM 接入**
   - 配置 `OPENAI_API_KEY` / `OPENAI_BASE_URL`，或使用国内兼容网关（通义千问 / 智谱 / DeepSeek）。
   - 在证据中心展示真实 AI 调用日志，证明不是模拟。
4. **文件存储**
   - 如需上传头像/证据截图，从 `local` 切换到对象存储（S3/MinIO/阿里云 OSS），避免容器重启丢失。

### Phase 4：日常可用性与落地（5–7 天）

目标：学生和学校愿意日常使用，而不是比赛完就弃用。

1. **每日提醒机制**
   - 浏览器推送通知 / 企业微信/钉钉/邮件，提醒今日训练/任务。
   - 连续打卡、薄弱维度复训提醒。
2. **内容运营闭环**
   - 学校端可定期发布新主题、更新知识库条目。
   - 知识库接入权威来源 RSS/公告自动同步（国家反诈中心、教育部等）。
3. **校园统一认证**
   - 将 `CAMPUS_AUTH_MODE` 从 `demo` 切到 `cas` 或 `oauth`，对接学校 CAS/企业微信。
4. **客户端封装（可选）**
   - 先用 PWA 实现“网页即应用”；如必须 App，再用 Tauri/Capacitor 打包。
5. **使用数据看板**
   - 学校端/辅导员端增加“学生参与率、完成率、风险检出数”等真实指标。

## 三、建议立即做的 3 件事（今天就能完成）

1. **删除登录页 Demo 入口并改文案**
   - 改 `src/pages/LoginPage.tsx`：去掉「演示账号一键进入」「校方发布端入口（保留后台路由但不放在登录页）」、去掉「离线可运行 · 数据本地化」标签。
   - 副标题改为「大学生 AI 主题学习与成果展示平台」。
2. **设置后端为强鉴权模式**
   - 复制 `backend/.env.example` 为 `.env`：`AUTH_REQUIRED=true`，`APP_SECRET=随机强密钥`。
   - 后端启动时读取新配置，前端确保注册/登录后携带 `Bearer Token`。
3. **给出联网部署地址**
   - 用 Docker Compose 在云服务器启动一次，拿到公网 IP/域名，替换前端 API 代理地址。
   - 如果暂无服务器，可先用 CloudStudio 沙箱部署一个可访问的预览版本。

## 四、验收标准（导师会问的）

- [ ] 打开网址 → 注册/登录 → 能看到首页，全程不需要任何“演示入口”。
- [ ] 关掉浏览器重新打开，登录态仍然保持（Token 持久化）。
- [ ] AI 风险检测/情景对话在配置 LLM 后能返回真实模型结果，证据中心有调用记录。
- [ ] 登录页没有渐变/粒子/玻璃态，3 秒内能说明产品价值。
- [ ] 手机端访问核心流程不崩、不横向滚动。
- [ ] 学校管理员能发布真实主题，学生端能看到并参与。

## 五、风险提醒

- **不要直接在生产环境删除旧 SQLite 数据**：迁移到 Postgres 前先备份。
- **关闭 `AUTH_REQUIRED=false` 后，未登录访问会 401**：需要同步确保前端路由守卫和 Token 刷新正常。
- **“演示账号一键进入”删除后，录屏/比赛现场需用真实账号演示**：提前在服务器里注册好 1–2 个演示账号并记录密码。
