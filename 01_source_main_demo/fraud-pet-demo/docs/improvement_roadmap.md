# 导师反馈系统完善方案

> 依据导师在群聊中提出的 6 条核心要求整理：
> 1. UI 要持续迭代，商业软件讲究简洁、明了、清晰；
> 2. 不局限于本地，要能联网；
> 3. 不给使用对象增加门槛，下载客户端或打开网页就能直接用；
> 4. 目标是做出客户端 / App / 网页端，登录后直接使用；
> 5. 带着交付、落地的目的去做，作品要符合真实使用逻辑、能被日常使用；
> 6. 不要带着演示、模拟的心态去做。

## 二、现状快照（已有但待激活的生产能力）

当前代码其实已经预埋了大量"真实产品"钩子，只是默认走演示态：

- **真实账号密码登录**：`backend/app/models.py` 已有 `Account` 表（username/password_hash/owner_id/role）；`LoginPage.tsx` 已有 login/register/campus 三种模式；后端 `.env.example` 已有 `AUTH_REQUIRED=false|true` 开关。
- **联网部署**：已有 `Dockerfile`（前端 Nginx 多阶段构建）、`backend/Dockerfile`、`docker-compose.yml`、健康检查。
- **数据库切换**：`.env.example` 已预留 `DATABASE_URL` 支持 PostgreSQL。
- **对象存储**：`.env.example` 已预留 S3/MinIO 配置，当前默认 `local`。
- **真实 LLM**：`.env.example` 已预留 `OPENAI_API_KEY`，不填则走规则引擎降级。
- **校园统一认证**：`.env.example` 已预留 CAS/OAuth 配置。
- **管理/审核端**：已有 `AdminAuditPage.tsx`、校方端 `/school/*`。

**结论**：系统距"可交付的真实产品"主要是"配置切换 + 去演示化 + UI 精炼"，而非从零重写。

## 三、分阶段完善路线图

### 阶段 1：去演示化与真实登录（1–2 天，P0）

目标：让系统第一次打开就是"真实可用"，而不是"请点演示模式"。

1. **登录入口默认真实化**
   - 文件：`src/pages/LoginPage.tsx`
   - 改动：
     - 生产环境（`import.meta.env.PROD`）隐藏"演示账号一键进入"和"校方发布端入口"；
     - 默认 mode 为 `'login'`，占位文案改为"账号""密码"；
     - 演示入口仅当 `VITE_DEMO_MODE=true` 时显示。
   - 后端：`backend/app/main.py` 或 auth 路由，生产环境 `AUTH_REQUIRED=true` 时拒绝 demo-login。

2. **移除 ownerId fallback**
   - 文件：`src/api/client.ts`（搜索 `?? 'U-2408**'`）
   - 改动：未登录时跳转 `/login`，不再默认填充演示 ownerId。

3. **默认启用鉴权**
   - 文件：`.env` / `.env.example`
   - 改动：生产部署时设置 `AUTH_REQUIRED=true`、`APP_SECRET=<随机强密钥>`。

4. **文案去 Demo 化**
   - 文件：`README.md`、`index.html`、各页面标题
   - 改动：
     - 标题从"大学生反诈主题学习..."改为已修正定位"大学生 AI 主题学习与成果展示平台"；
     - 删除"Demo 态""演示"等字样；保留"启智杯参赛作品"可在 about/foot 中说明。

### 阶段 2：UI 商业化精简（2–3 天，P0）

目标：像一门课表 App、学习通、钉钉教育版那样"看得懂、不花哨"。

1. **登录页去装饰**
   - 文件：`src/pages/LoginPage.tsx`
   - 改动：
     - 移除粒子动画、径向渐变、网格背景、发光阴影、书法字特效；
     - 改为白底/浅灰底 + 品牌单色（如紫色 `#534AB7`）的扁平卡片；
     - 左侧面板只保留 Logo、一句话价值主张、3 个简洁卖点；
     - 移除 emoji（`👋✨🎓`），用无表情文案替代；
     - 表单标签、错误提示、按钮文案统一字号与字重。

2. **建立设计系统**
   - 文件：`tailwind.config.js` / `src/components/ui/*`
   - 改动：
     - 固定主色板（建议 1 个主色 + 1 个语义色 + 灰阶）；
     - 统一卡片圆角、按钮高度、表单间距；
     - 减少"玻璃拟态"（`glass-dark`）使用场景，改为实色面。

3. **首页信息层级与留白**
   - 文件：`src/pages/HomePage.tsx`
   - 改动：
     - 一屏内最多 2 个视觉焦点：能力画像 + 知识库入口；
     - 快捷入口收进底部导航或二级页，避免 8+ 图标堆叠；
     - 增加段间距，使用 16/24/32 的倍数留白。

4. **能力画像与知识库保持已修正样式**
   - 确保能力画像中性五维、知识库多主题来源标注的 UI 保持清晰可读。

### 阶段 3：联网部署与数据持久化（1–2 天，P0）

目标：评委打开的是一个真实网址，而不是你的本机 `localhost`。

1. **云服务器 + Docker Compose 部署**
   - 文件：`docker-compose.yml`
   - 改动：
     - 新增 `postgres` 服务，后端 `DATABASE_URL` 指向 PostgreSQL；
     - 前端 `VITE_API_BASE_URL=https://your-domain.com/api`；
     - Nginx 配置 `nginx.conf` 增加 HTTPS 反代、静态缓存、gzip。
   - 操作建议：购买/使用校园提供的云服务器（阿里云/腾讯云/华为云学生机），域名备案或直接使用 IP + HTTPS（可用 Cloudflare 免费证书）。

2. ** secrets 管理**
   - 不在代码仓库保存 `.env` 生产值；使用服务器环境变量或 Docker secrets。

3. **健康检查与监控**
   - 文件：`backend/app/main.py` 已有 `/api/health`
   - 补充：数据库连接探针、LLM 可用性探针、磁盘/内存基础监控。

### 阶段 4：真实 AI 与每日使用闭环（3–5 天，P1）

目标：用户每天愿意打开 5 分钟，而不是录完视频就关掉。

1. **接入真实 LLM**
   - 文件：`.env`
   - 改动：配置 `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL`；
   - 建议：使用国产低成本模型（通义 qwen-turbo、DeepSeek、智谱 glm-4-flash），价格低于 GPT-4o，更适合校园场景。

2. **每日一练 + 打卡**
   - 新增/改造：
     - 首页"今日任务"卡片；
     - 连续打卡天数、每日提醒（可先做前端本地提醒）；
     - 完成后给盾能/宠物成长值。

3. **学习规划可执行**
   - 文件：`src/pages/LearningWorkspacePage.tsx` / `TaskPackagePage.tsx`
   - 改动：任务包支持"开始/完成/跳过"状态，后台真实记录完成率。

4. **校方端真实活动发布**
   - 文件：`src/pages/SchoolActivityPage.tsx`、`backend/app/routers/activities.py`
   - 改动：
     - 校方发布活动后，学生端可见真实参与按钮；
     - 活动结束可导出参与名单（匿名化后给学校）。

5. **内容审核**
   - 文件：`src/pages/AdminAuditPage.tsx`
   - 改动：学习集市发布的内容先审后发，避免UGC风险。

### 阶段 5：客户端扩展（赛后，P2）

- **PWA**：最快路径，添加 `manifest.json` 和 Service Worker，可安装到手机桌面、离线查看知识库。
- **微信小程序**：如需覆盖国内大学生，后续用 Taro/Uni-app 复用部分业务逻辑。
- **Flutter / React Native**：如需独立 App，成本较高，建议赛后视反馈再决定。

## 五、对 Demo 视频/答辩的直接影响

按导师要求，演示时应尽量避免"这是我们的演示账号，点一下就能进"这类话术，改为：

- **开场**："这是一个已部署在 XXX 的真实系统，我现在用普通学生账号登录。"
- **登录**：输入真实注册的账号密码，走正常登录流程。
- **数据**：展示云端真实数据（排行榜、学习集市、校园活动）而非本地 mock。
- **价值**：强调"学校可以直接部署给学生日常使用"，而不是"这是一个 Demo"。
