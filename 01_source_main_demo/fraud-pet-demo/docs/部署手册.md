# 部署手册 —— 诈醒学集 · AI 学习集市

> 文档版本：v1.0 ｜ 项目级交付物  
> 适用范围：本地 / 测试服务器 / 云服务器稳定部署

## 1. 部署架构

```
浏览器 ──HTTP──> [frontend 容器] nginx:80
                        │  /api 反向代理
                        ▼
                  [backend 容器] uvicorn:8000 ──> SQLite (db-data 卷)
```

- **前端**：多阶段 Dockerfile（Node 构建 → Nginx 部署），`nginx.conf` 将 `/api/` 代理到后端容器。
- **后端**：`python:3.13-slim` + `uvicorn app.main:app`，SQLite 持久化于 `db-data` 卷。
- **编排**：`docker-compose.yml` 管理两服务，`restart: unless-stopped`（崩溃自启），backend 健康检查通过后 frontend 再启动。

## 2. 环境要求

- 一台 Linux 服务器（或本地 Linux / WSL），已安装 **Docker ≥ 24** 与 **Docker Compose v2**。
- 最低配置：1 核 2G（演示级足够）；磁盘 ≥ 10GB。
- 公网访问需开放 **80**（及可选 443）端口；如需域名 + HTTPS 另装 Caddy/Traefik。

## 3. 方式一：Docker 一键部署（推荐）

```bash
# 1) 获取代码（推荐 git 干净克隆，避免把 node_modules / 备份打进去）
git clone <仓库地址> fraud-pet-demo && cd fraud-pet-demo

# 2) （可选）配置 AI 能力：不填则自动降级规则引擎，演示照样能跑
cp backend/.env.example backend/.env
#   编辑 backend/.env，填写 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL

# 3) 构建并后台常驻启动
docker compose up -d --build

# 4) 查看状态与日志
docker compose ps
docker compose logs -f

# 5) 防火墙放通 80 端口 → 浏览器访问 http://<服务器公网IP>
```

### 3.1 前端 API 基地址（重要，已修复）

容器内前端通过相对路径 `/api` 调用，由 nginx 反代到后端，无需硬编码地址。构建时由根 `Dockerfile` 注入 `VITE_API_BASE_URL=/api`；如需独立域名部署，可覆盖：

```bash
docker compose build --build-arg VITE_API_BASE_URL=https://your.domain.com/api
docker compose up -d
```

> 历史版本曾默认 `http://127.0.0.1:8000/api`，会导致部署后前端把请求打到访客本机而失效；当前已修正为默认 `/api`。

## 4. 方式二：非 Docker 手动部署

```bash
# 后端
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # 按需填 LLM_*
uvicorn app.main:app --host 0.0.0.0 --port 8000

# 前端（另开终端）
npm install
# 本地联调用 npm run dev（vite 代理 /api）；生产用：
VITE_API_BASE_URL=/api npm run build
# 将 dist/ 交给 Nginx 托管，并配置 /api 反代到 http://127.0.0.1:8000
```

Nginx 反代片段（生产前端）：

```nginx
location /api/ { proxy_pass http://127.0.0.1:8000/api/; proxy_set_header Host $host; }
```

## 5. 环境变量说明

**后端 `backend/.env`**：
| 变量 | 默认 | 说明 |
|---|---|---|
| `DATABASE_URL` | `sqlite:///../data/demo.sqlite3` | 可改 PG/MySQL 连接串 |
| `LLM_API_KEY` | 空 | 不填 → 规则引擎降级 |
| `LLM_BASE_URL` | 空 | OpenAI 兼容地址 |
| `LLM_MODEL` | `rule-engine` | 模型名；空则用规则引擎 |
| `DEBUG` | `false` | 生产设 false |
| `PORT` | `8000` | 服务端口 |

**前端构建期**：`VITE_API_BASE_URL`（默认 `/api`）。

## 6. 公网暴露与 HTTPS（推荐）

使用 Caddy 做反向代理并自动申请证书：

```bash
# 服务器安装 caddy 后：
caddy reverse-proxy --from your.domain.com --to localhost:80
```

或在 `docker-compose.yml` 前置一层 Caddy/Traefik 服务。域名 DNS 解析到服务器公网 IP 即可。

## 7. 数据持久化与备份

- Docker：数据在 `db-data` 卷，重启不丢；备份：`docker compose down` 后拷贝卷，或 `docker cp` 容器内 `/app/backend/data/demo.sqlite3`。
- 非 Docker：直接备份 `backend/data/demo.sqlite3`。

## 8. 升级与回滚

```bash
git pull
docker compose up -d --build     # 升级
# 回滚：git checkout <旧提交> && docker compose up -d --build
```

## 9. 常见问题排查

| 现象 | 排查 |
|---|---|
| 前端能开但所有接口 404/网络错误 | 确认浏览器访问的是 nginx(80) 而非 backend(8000)；生产必须走 `/api` 相对路径 |
| 接口 500 | 看 `docker compose logs backend`；多为 `.env` 缺失或 DB 权限 |
| 数据丢失 | 确认 `db-data` 卷已挂载，未误删卷 |
| AI 功能无响应 | 未配 `LLM_API_KEY` 时属正常降级；配了仍异常检查 `LLM_BASE_URL` |
| 端口冲突 | 改 `docker-compose.yml` 主机映射（如 `8080:80`） |
