# 数据库设计 —— 诈醒学集 · AI 学习集市

> 文档版本：v1.0 ｜ 项目级交付物

## 1. 选型与约定

- **主库**：SQLite（`DATABASE_URL=sqlite:///../data/demo.sqlite3`），文件落盘于 `backend/data/`。
- **可切换**：通过环境变量 `DATABASE_URL` 可直接切换为 PostgreSQL / MySQL（如 `postgresql://user:pwd@host:5432/db`），ORM 层为 SQLAlchemy，业务代码无数据库方言耦合。
- **建表策略**：应用启动时 `Base.metadata.create_all(engine)` 自动建表；并在 `create_app` 内执行轻量迁移 helper（`_migrate_pets_table` / `_migrate_v3_columns`）兼容历史字段。无需手动执行 Alembic 即可冷启动。
- **会话**：每个请求独立 `Session`（`get_db` 依赖），`check_same_thread=False` 适配 SQLite 多线程。
- **命名**：蛇形表名、主键 `id`（字符串业务主键，由 `_new_id` 生成），时间戳统一 `created_at`（部分表含 `updated_at`）。

## 3. 核心关系

- `learning_goals (1) ── (N) learning_plans`：一个目标生成一份任务包（旧任务包自动置 `paused`）。
- `learning_plans (1) ── (N) learning_plan_items`：任务包含多个任务项。
- `learning_plans (1) ── (N) learning_artifacts`：任务包下可提交多个成果。
- `learning_artifacts (1) ── (N) learning_artifact_versions`：成果多版本迭代。
- `learning_market_listings` 通过 `resource_type + resource_id` 软引用 plan/artifact，不物理外键，便于共享流转。
- `users.owner_id` 是贯穿所有业务表的所有权键（演示态由登录生成）。

## 4. 索引与约束

- 业务查询均以 `owner_id` 过滤，建议（PostgreSQL/MySQL 下）为 `owner_id`、`status`、`goal_id`、`plan_id` 建索引；SQLite 演示规模下当前无性能瓶颈。
- `learning_market_listings.status` 用于"已发布"过滤（`get_market` 仅返回 `published`）。
- 隐私：成果 `visibility` 控制公开/私密；"仅好友"需后续好友关系表支撑。

## 5. 数据迁移与备份

- **冷启动**：拷贝仓库后首次 `docker compose up` 自动建表，无需迁移脚本。
- **字段演进**：历史兼容由 `create_app` 内迁移 helper 处理；后续可接入 Alembic 做版本化迁移。
- **备份**：SQLite 场景直接备份 `backend/data/demo.sqlite3`；Docker 场景备份 `db-data` 卷（`docker compose down` 后拷贝卷或 `cp` 容器内 `/app/backend/data`）。
- **切换数据库**：设置 `DATABASE_URL` 指向 PG/MySQL，重启即由 `create_all` 建表（建议先 `CREATE DATABASE`）。
